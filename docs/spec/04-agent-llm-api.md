## 10. Agent

### 10.1 Interface
Both agents (mock and live) implement:
```python
async def run(incident_id: str, alert_text: str, emit: Callable[[Event], Awaitable[None]]) -> FinalReport
```
Both agents call the **real MCP tools** through `backend/mcp_bridge.py`. Both emit the **same events** (Section 11).

### 10.2 LLM adapter (provider-neutral)

**Rule: `agent_live.py` must never import `google.genai` or `anthropic`.** It only uses the types below. All provider code lives in `backend/llm/`.

Files:
```
backend/llm/__init__.py        # make_session(...) factory
backend/llm/base.py            # dataclasses + LLMSession Protocol
backend/llm/schema.py          # simplify_schema(), assert_simple_schema()
backend/llm/gemini_client.py   # GeminiSession (REQUIRED)
backend/llm/anthropic_client.py# AnthropicSession (OPTIONAL, skip by default)
backend/llm/fake_client.py     # FakeSession (scripted, for tests)
```

`base.py` (write exactly these names):
```python
@dataclass
class ToolSpec:   name: str; description: str; input_schema: dict      # simple JSON Schema
@dataclass
class ToolCall:   id: str; name: str; args: dict                        # id is generated by us (uuid4 hex[:8])
@dataclass
class ToolResult: call_id: str; name: str; content: dict; is_error: bool = False   # content = parsed MCP envelope
@dataclass
class LLMTurn:    text: str; tool_calls: list[ToolCall]                 # text may be "" ; tool_calls may be []

class LLMSession(Protocol):
    async def send_user(self, text: str) -> LLMTurn: ...
    async def send_tool_results(self, results: list[ToolResult]) -> LLMTurn: ...
```
Each session object **owns its own conversation history** internally. The agent loop never builds provider messages.

Factory: `make_session(provider: str, system: str, tools: list[ToolSpec]) -> LLMSession`. `provider` comes from env `LLM_PROVIDER` (`gemini` default).

### 10.2.1 Tool schema rules (so Gemini accepts every tool)
1. Pydantic models for tool inputs must **not** use `Optional[...]` or unions. Use a default value instead (`max_hops: int = 3`).
2. `simplify_schema(schema)` must: inline every `$ref`/`$defs`; delete `title` and `default` keys; convert `anyOf: [X, {type: null}]` to `X`; keep only `type`, `properties`, `required`, `enum`, `items`, `description`, `minimum`, `maximum`.
3. `assert_simple_schema(schema)` raises if any other key (including `anyOf`, `oneOf`, `allOf`, `$ref`, `$defs`) remains.
4. Test (`tests/test_schema_simple.py`): list all MCP tools, simplify each schema, call `assert_simple_schema`. This test must pass before any Gemini call is attempted.
5. Every tool description must contain two sentences starting `Use when:` and `Do not use when:`.

### 10.2.2 GeminiSession (REQUIRED). Implementation recipe

**Do not rely on memory for SDK names. In T8a, print the real field names from the installed SDK (see T8a) and fix this recipe if any name differs; log differences in `DECISIONS.md`.**

Facts (verified from Google docs):
- Package: `google-genai`. Import: `from google import genai` and `from google.genai import types`.
- Model id: `gemini-3.8-flash`. Thinking levels: `low`, `medium`, `high`. `minimal` is not supported and returns an error. Never set `thinking_level` and `thinking_budget` together.
- Gemini 3 **requires thought signatures to be sent back** during function calling. If you append the model's **entire response content object unchanged** to the history, the SDK handles signatures. If you rebuild, trim or "clean" the model's content, the API returns a 400 error ("function call ... is missing a thought_signature").
- Function declarations accept JSON Schema through `parameters_json_schema`.
- Automatic function calling must be **disabled** (we run our own loop through MCP).

Recipe:
```python
from google import genai
from google.genai import types

class GeminiSession:
    def __init__(self, api_key, model, thinking_level, system, tools):
        self.client = genai.Client(api_key=api_key)
        self.model = model
        decls = [types.FunctionDeclaration(name=t.name, description=t.description,
                                           parameters_json_schema=t.input_schema) for t in tools]
        self.config = types.GenerateContentConfig(
            system_instruction=system,
            tools=[types.Tool(function_declarations=decls)],
            automatic_function_calling=types.AutomaticFunctionCallingConfig(disable=True),
            thinking_config=types.ThinkingConfig(thinking_level=thinking_level),
        )
        self.contents: list[types.Content] = []   # full history, owned by this object
        self._pending: list[ToolCall] = []        # calls from the last model turn, in order

    async def send_user(self, text):
        self.contents.append(types.Content(role="user", parts=[types.Part.from_text(text=text)]))
        return await self._generate()

    async def send_tool_results(self, results):
        # one Content, role "user", one function_response Part per call, SAME ORDER as the calls
        parts = [types.Part.from_function_response(name=r.name, response=({"error": r.content} if r.is_error else {"output": r.content}))
                 for r in results]
        self.contents.append(types.Content(role="user", parts=parts))
        return await self._generate()

    async def _generate(self):
        resp = await self.client.aio.models.generate_content(model=self.model, contents=self.contents, config=self.config)
        content = resp.candidates[0].content
        self.contents.append(content)             # VERBATIM. Never edit this object.
        text = "".join(p.text for p in content.parts if getattr(p, "text", None) and not getattr(p, "thought", False))
        calls = [ToolCall(id=uuid4().hex[:8], name=p.function_call.name, args=dict(p.function_call.args or {}))
                 for p in content.parts if getattr(p, "function_call", None)]
        return LLMTurn(text=text, tool_calls=calls)
```
Rules for this class:
1. **Never** modify, filter, reorder or drop parts of `content` before appending it to `self.contents`.
2. If the model returns several function calls in one turn, the loop must run **all** of them and send **all** results in **one** `send_tool_results` call, in the same order.
3. Wrap `generate_content` in a retry helper: up to 3 attempts, exponential backoff (1s, 2s, 4s) on HTTP 429 and 5xx. Do not retry 400 errors; raise `LLMError` with the message.
4. Add a per-call timeout of 60 s.
5. Do not set `temperature` (leave the default) unless T8a shows unstable tool calls; if you change it, log it in `DECISIONS.md`.
6. `response` from `from_function_response` must be a dict. Our `content` is already a dict (the parsed MCP envelope). Wrap it as shown (`output` / `error` keys).
7. Read the API key from env `GEMINI_API_KEY`. Never print it or commit it.

### 10.2.3 Live agent loop (`agent_live.py`), provider-neutral

Pseudo-code (implement this exactly; all names are from this spec):
```
tools = [to_toolspec(t) for t in mcp.list_tools()]       # simplify_schema applied
session = make_session(provider, SYSTEM_PROMPT, tools)
turn = await session.send_user(alert_text)
calls_made = 0; seen = Counter()
while True:
    if turn.text.strip(): emit(thought(turn.text))
    if not turn.tool_calls: break                          # final answer
    results = []
    for call in turn.tool_calls:
        calls_made += 1
        if calls_made > 12: abort("tool call cap reached")
        key = (call.name, json.dumps(call.args, sort_keys=True)); seen[key] += 1
        if seen[key] > 2: abort("repeated identical call")
        emit(tool_call(call))
        envelope = await mcp.call(call.name, call.args)    # dict (parsed envelope)
        emit graph_visit / tool_result / risk_update / action / verification per Section 11
        if tool is propose_containment and decision == APPROVAL_REQUIRED:
            emit(approval_required); wait for approval future (APPROVAL_TIMEOUT_S; AUTO_APPROVE=true approves at once)
            on approval: orchestrator marks the Action approved (not the LLM). On timeout: emit error(recoverable=true), tell the model "approval timed out; do not execute", continue.
        results.append(ToolResult(call.id, call.name, envelope, is_error=not envelope["ok"]))
    turn = await session.send_tool_results(results)
final = parse_report(turn.text)        # fenced JSON block -> FinalReport (Pydantic)
if invalid: one retry: turn = await session.send_user("Return only the final JSON report in a ```json block."); parse again
if still invalid: build the report deterministically from recorded tool results
```
Other rules:
- Tool errors are returned to the model as `ToolResult(is_error=True)`. The loop never crashes on a tool error.
- `abort(...)` emits `error(recoverable=false)` and a deterministic partial report.
- Emit `verification` only from the **`execute_containment` / `rollback_action` result**, never from model text.
- All numbers in `tool_result.summary` are built by code from the envelope, never by the model.

### 10.2.4 Extra hardening for a fast, lower-tier model
Add these to `prompts.py` text and to the loop:
1. System prompt contains a numbered **playbook per alert type** (security alert, outage alert, vague alert). The model fills in node IDs; it does not invent the workflow.
2. System prompt states: "Call one tool at a time unless two calls are independent."
3. System prompt states: "Node IDs must be copied exactly from the alert or from a previous tool result."
4. If the model's first turn has no tool call, send one corrective message: "You must call a tool. Start with get_component_context."
5. If a tool returns `NOT_FOUND`, the loop adds the hint "Check the ID spelling against previous results."

### 10.3 Mock agent (`agent_mock.py`): deterministic, no API key
Scripted per scenario (parse the alert text for the scenario, or take `scenario` from the API). Must call the **real MCP tools** (so graph behavior is genuinely exercised) and emit the same events, with canned `thought` strings.

- **A (attack on `svc-payments-gateway`):** `get_component_context` → `compute_risk` → `find_attack_paths` → `get_failure_impact(3)` → `propose_containment(REVOKE_ROLE)` (AUTO) → `execute_containment` → `find_attack_paths` (verify: 1 target left) → `propose_containment(ISOLATE_NODE)` (APPROVAL_REQUIRED) → pause for approval → `execute_containment` → `find_attack_paths` (verify: 0) → `notify_owners(team-payments)` → `record_finding` → report.
- **B (`db-orders` unreachable):** `get_component_context` → `get_failure_impact(3)` → `rank_critical_components(5)` → `notify_owners(<4 owning teams>)` → `record_finding` → report (no containment).
- **C (`svc-config` exploitable CVE, false alarm):** `get_component_context` → `compute_risk` → `find_attack_paths` (0) → `get_failure_impact(3)` → `propose_containment(ISOLATE_NODE)` (DENIED) → `record_finding` ("do not isolate: 17 dependents, no verified PII path; patch within SLA") → report.

### 10.4 System prompt (`prompts.py`, essentials, write in full)
- Role: incident-response agent whose **only source of facts is the graph tools**.
- "Never state a node ID, edge, or number a tool did not return."
- Think in hops; before each tool call state a one-line hypothesis.
- Distinguish **failure impact** (who breaks) from **attacker reach** (what can be accessed).
- Always call `compute_risk` for security alerts; use `propose_containment` before `execute_containment`; prefer the least disruptive action that reduces attack paths; verify by re-running `find_attack_paths` after executing.
- Respect policy: never retry a DENIED action; if APPROVAL_REQUIRED, wait; do not try to work around it.
- Always notify owning teams and `record_finding` before finishing.
- Final output: the JSON report in a fenced block.

### 10.5 Final report schema (Pydantic `FinalReport`)
```json
{"incident_id":"", "summary":"", "risk_score":0.0,
 "findings":[{"claim":"","evidence_refs":["<tool_call_id>"]}],
 "impact":{"impacted_services":0,"customer_facing":0,"owner_teams":[""]},
 "actions":[{"action_id":"","type":"","target":"","policy":"","status":""}],
 "verification":{"targets_before":[],"targets_after":[]},
 "tool_calls":[{"call_id":"","tool":"","ms":0,"query_id":""}]}
```
Server-side validator: every node ID mentioned in `findings[].claim` that matches `^(svc|db|role|team)-[a-z-]+$` must appear in some tool result of this incident; otherwise strip that claim and log a warning. (This is the anti-hallucination guard.)

## 11. Backend API and Event Contract

| Endpoint | Behavior |
|---|---|
| `GET /health` | `{ok:true, graph:"infra", nodes:N}` |
| `GET /graph` | `{nodes:[{id,label,props}], edges:[{id:"src\|REL\|dst", source, target, type, props}]}` (excludes Incident/Finding/Action) |
| `GET /scenarios` | `[{id:"A",title,alert_text},...]` (alert texts below) |
| `POST /incidents` | body `{scenario?:"A"\|"B"\|"C", text?:str, mode?:"live"\|"mock"}` → `{incident_id}`; starts the agent as a background task |
| `GET /incidents/{id}/stream` | SSE; replays buffered events then live ones; closes after `final_report` or `error(recoverable=false)` |
| `GET /incidents/{id}/events` | JSONL of all events (used by replay) |
| `POST /actions/{action_id}/approve` | body `{approved_by:str}`; resolves the pending approval future; 404 if none |
| `POST /actions/{action_id}/rollback` | calls `rollback_action` via MCP; returns result |
| `POST /admin/reset` | re-seeds graph; clears event buffers |
| `GET /replays/{scenario}` | serves `replays/scenario_x.jsonl` |

Alert texts:
- A: `CRITICAL: CVE-2026-9901 (CVSS 9.8, exploit available) detected on svc-payments-gateway.`
- B: `ALERT: db-orders is unreachable; connection timeouts reported across services.`
- C: `HIGH: CVE-2026-4418 (CVSS 8.1, exploit available) detected on svc-config.`

**Event envelope:** `{"seq":int,"ts":"ISO","type":"<below>","data":{...}}`; SSE `event:` equals `type`.

| type | data |
|---|---|
| `incident_started` | `{incident_id, alert_text, mode}` |
| `thought` | `{text}` |
| `tool_call` | `{call_id, tool, args}` |
| `graph_visit` | `{call_id, kind, node_ids, edge_keys}` (**from tool envelope only**) |
| `tool_result` | `{call_id, ok, summary, query_id, cypher, ms}` (`summary` = ≤200-char string built in code, not by the LLM) |
| `risk_update` | `{risk, components}` |
| `approval_required` | `{action_id, action, target_id, reason}` |
| `action` | `{action_id, action, target_id, status, policy}` |
| `verification` | `{action_id, targets_before, targets_after}` |
| `final_report` | `FinalReport` |
| `error` | `{message, recoverable}` |
